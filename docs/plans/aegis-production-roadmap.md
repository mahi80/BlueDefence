# AEGIS / Agent Q — production roadmap (resume-safe)

**Purpose of this file:** the single place a new session reads to continue the
AEGIS build without the old conversation. Every step has a status line; update
it in the same PR that does the work. If you are a fresh session: read this
file, then `NEXT_SESSION.md`, then the step's "Where" files — nothing else is
needed to resume.

Owner: Mahi. Code: `mahi80/rbi`, the `aegis/` package on **`main`** (promoted in
0.6, PR #105; it was built on `Agentic_Endpoint_AEGIS`). The internal plane (ACP SDK +
dashboard) is on `main` too and is what AEGIS plugs into.

Status legend: `[ ]` not started · `[~]` in progress (branch named) · `[x]` merged · `[-]` dropped

## The two planes in one line each

- **Internal (built, live):** `acp-sdk` inside every AI agent → 37 controls in-process
  → heartbeat every 10 s → dashboard scanners → pause-gate (423) stops a rogue agent.
- **External (prototype):** bank telemetry (WAF/SASE/EDR/SIEM/intel) → Agent Q
  orchestrator + specialists → evidence chain → `ResponseAgent` → *today a mock* →
  must become vendor enforcement.

Order of work: **brain → hands → swarm → learning.** Connectors before swarm (a swarm
that cannot enforce is a faster report); fine-tune last (it needs the data the loop makes).

## Governed autonomy — the line autonomy grows within

The "single brain that spawns a swarm to defend" grows along **two independent axes** (enforcement and learning), each inside a fixed lattice: **reversible or time-boxed, audited before it takes effect, human-overridable, off by default.** Irreversible or high-blast actions never auto-fire; a model never promotes itself; the two axes never auto-escalate each other. This is the HITL story the product sells, stated as the spec the code is built against — not a limitation, the moat.

**Enforcement autonomy — tiered auto-block** (`aegis/agents/response/autonomy.py::AutonomyPolicy`, flag `AEGIS_AUTO_BLOCK`, deliberately *separate* from `AEGIS_ENFORCEMENT_MODE` so flipping challenge/throttle live cannot silently make blocks autonomous):

| Mode | What runs without a human | Flag |
|---|---|---|
| **off** | nothing — every block waits for a human | `AEGIS_AUTO_BLOCK=off` |
| **shadow** (default) | nothing acts; an eligible block is recorded as a "would-have-auto-blocked" receipt and still goes to a human; `aegis.shadow report` scores it against the analyst's decision | `AEGIS_AUTO_BLOCK=shadow` |
| **live** | a `block` runs now, self-expiring, **only when all hold**: verdict `malicious` ∧ confidence ≥ `AEGIS_AUTO_BLOCK_MIN_CONF` (0.90); independent voter did not dissent (`metadata.vote_concur ≠ False`); target is narrow-external (public IP, CIDR ≤ /24 v4 or /48 v6, or a TLS fingerprint **paired with an exact non-browser UA** — a bare JA4 or a `Mozilla/` UA is never auto-blocked, it could be customers); not in `AEGIS_PROTECTED_TARGETS` / `AEGIS_FP_ALLOW`; under `AEGIS_AUTO_BLOCK_MAX_PER_HOUR` (50). Applied with `AEGIS_AUTO_BLOCK_TTL` (900 s) — the connector rolls it back. | `AEGIS_AUTO_BLOCK=live` |

- **Auto-safe actions** (`throttle`, `challenge`, `monitor`, `notify`) graduate on their own axis via `AEGIS_ENFORCEMENT_MODE` + the 1.5 shadow window (flip lowest-blast-radius first).
- **Containment** — `isolate`, `revoke_sessions`, `lock_account`, `rotate_credential`, `kill_process` — **is never in auto scope; always a human**, with the two-person rule on `AEGIS_PROTECTED_TARGETS` (1.1 / 1.4).
- **Fails safe**: over `MAX_PER_HOUR` the budget is spent → waits for a human; `AEGIS_ENFORCEMENT_MODE=shadow` drops everything back to demonstrated instantly.

**Learning autonomy — the retrain loop** (3.5, `aegis/finetune/retrain.py`): export → build → train → gate (≤ 5 misses/37, 0 injection leaks, now + a tracked `network` suite) → shadow (candidate vs current on analyst-decided alerts newer than its training export; n ≥ 20, agreement ≥ current − 2 pt) → propose in the dashboard approvals queue → human accepts → sync to `current.json`. **A model never self-promotes** — v6 failed the gate on 2026-10-25 (30/37) and did not ship. Promotion rides the *same* approvals queue as rule acceptance (3.1).

**The coupling rule:** a model promotion **never** automatically raises the enforcement tier. A new model enters at the mode the previous one held; moving `AEGIS_AUTO_BLOCK` off → shadow → live is its own human decision, gated on the shadow report. This blocks the "better model → more autonomy" auto-escalation a regulator would reject.

**Graduation criteria** (how a mode flips — a bar, not a date): the `aegis.shadow report` thresholds — n ≥ 20, reviewed ≥ 10, 14 days, ≥ 95 % agreement with analysts, 0 connector failures — decide `ready`, lowest-blast-radius action first; set **per business unit**, so Lending can sit at `shadow` while a sandbox BU runs `live`. Every autonomous action writes its evidence chain + the authorising mode to the audit log (Postgres) **before** it takes effect — which is exactly the RBI FREE-AI / EU AI Act requirement: auditability, human oversight, no silent drift.
